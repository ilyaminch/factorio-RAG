# Embeddings and vector search

`index.py` embeds processed chunks and uploads them to local Qdrant. `query.py` prints matching passages, titles, sections and similarity scores. The original database logic is preserved; only the indexer's input path is adjusted for the relocated layout. LLM answer generation is a planned next step.

| Setting | Value |
| --- | --- |
| FastEmbed model | `BAAI/bge-small-en-v1.5` |
| Vector size / metric | 384 / Cosine |
| Collection | `factorio_wiki` |
| Storage | `./qdrant_db`, relative to the working directory |
| Upload batch | 100 chunks |

Settings are defined separately in each script. FastEmbed downloads the model on first use; see the [official quickstart](https://qdrant.tech/documentation/fastembed/fastembed-quickstart/).

## Indexing

Input: `data/processed/chunks.jsonl` at the project root, generated by [data_pipeline](../data_pipeline/README.md).

Run from the repository root in the configured Python environment:

```powershell
python -m src.database.index
```

Each chunk UUID becomes a point ID; its text and metadata become the payload. Upsert updates matching IDs, but changed chunks get new IDs and old points remain. For a complete rebuild, close database processes, move the existing `qdrant_db/` to a backup folder and run indexing again.

## Search

```powershell
python -m src.database.query
```

The query is fixed in the script: `Recipe: steel plate`, limit 10, section filter `Characteristics`. There are no CLI options. The filter excludes sections named `Characteristics / Base game` or `Characteristics / Space Age mod`. Indexing and search must use the same model and vector size. Run them sequentially: local storage is opened by one process at a time.
